# Task 2 项目复盘

2026-09-12。材料依据[TESTS](../REVIEWS/TASK2-TESTS.md)和真实实现核对；个人是否能独立讲述仍需本人练习，代理不代签。

## 30 秒介绍

这是用 Kuikly 做的股票问答原型。用户提问后，回答既有 Markdown 摘要，也有能核对的行情证据卡。点击某条依据可以进入对应股票、快照和区间的详情，再返回原会话继续追问。首版用确定性 Mock，主要解决“AI 信息如何被理解和核对”，而不是证明模型预测能力。

## 职责与路径

用户提出约90分目标、工作区安装与自主推进约束；Windows Codex完成方案选择、业务实现、测试、文档和本地交付准备。应如实说明AI编程协作，不把代理写的每一行都说成独立手写。

体验路径：输入“比较 A 和 B”→Markdown说明口径→A/B各自证据卡→点击B的局部反弹→详情选中+5.49%→返回原会话→追问B风险→检验B缺量→倍数不可用但价格依据仍在。

## 架构和五个关键选择

1. **内容先分类型。** Markdown和EvidenceCard分别建模。实体标识和行情快照随业务块传递，不从自然语言里猜路由。因此格式变化不会把用户送到另一只股票。
2. **一条请求一张票据。** 票据包含代次、消息ID、原问题、上下文和场景。取消、新会话让旧票据失效，重试保留原位置和上下文。消息列表不会因迟到响应串线。
3. **真实复用现有能力。** 聊天卡复用Task1的EvidenceResolver和LensPresenter，展开走势复用MarketPlot，详情复用FinanceDetail/QuoteEvidenceLens。单股票、A/B比较和缺量共用EvidenceAnswerCard。
4. **会话与视图分开。** Pager持有ChatController/ChatSession；离开聊天看详情不会销毁记录。卡片展开状态以消息ID和快照键保存，避免A/B或两条回答相互影响。
5. **有边界地支持Markdown。** 只渲染受限文本块和样式；不执行HTML、不加载图片、不打开外链。JVM单测之外还要看浏览器：本轮确实发现了JS Unicode正则与JVM接受范围不同的问题并修复。

## 十个面试问题

**1. 和普通聊天框区别？** 不只读文字，用户可以直接核对依据对应的行情、时间与计算式，并从同一实体继续追问。

**2. 真实用了AI模型吗？** 没有。提供确定性规则模板与Mock数据，重点证明AI信息载体与业务交互。接模型需要遵守typed内容合同和事实校验。

**3. 为什么不用HTML渲染Markdown？** 会引入脚本、远程图片和链接行为。当前文本样式已满足题面和演示，受限renderer跨端更可控。

**4. 如何避免旧结果覆盖新会话？** 请求必须等于当前pending票据；取消/reset后旧票据失效，即便计时回调还运行也不会更新记录。

**5. 重试会重复提问吗？** 不会。重试替换失败回答，保留消息ID、问题和股票上下文，只更新代次与attempt。

**6. 为什么不保存到本地？** 首版没有登录或云同步需求；生命周期内状态已经支持来回查看，明确刷新清空能避免伪装成持久会话。

**7. 如何证明可复用？** A/B同屏调用相同卡片，缺量走同一组件；Task1详情与Task2卡片消费同一事实层，展开图共用MarketPlot，有运行与单测证据。

**8. 比较的口径是什么？** 相同20日窗口，各自起点计算涨跌幅、各自此前五日均量计算倍数。不能把较高价格或较大倍数直接理解成更好投资。

**9. 最有价值的失败是什么？** JVM通过但浏览器正则报错，以及vfor内两个根节点导致运行失败。这证明编译/单测不能替代真实UI链路。

**10. 下一步真正需要做什么？** 用户个人练习讲述；若扩展平台，先保持工作区隔离验证Android设备与键盘，再决定是否接真实服务。当前不自动发布。
