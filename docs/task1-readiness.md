# Task 1 阶段准备合同

## 题面依据与起点

- Task 1 的 Must 与完成定义只以 `docs/REQUIREMENTS.md` 为准；Issue #1477、旧归档和图表类型不扩张题面。
- 当前活动工程从 `finance_home` Android/H5 空壳继续，`archive/task1-v1/` 只供考古，不提供兼容合同，也不计入完成度。
- 固定阶段为 `T1-PLAN → T1-CODE → T1-TESTS → T1-LEARNING`，不再拆分 Feature 任务卡。

## 阶段责任

| 阶段 | Owner | 入口 | 唯一产物 | 完成门 |
|---|---|---|---|---|
| PLAN | Codex | 题面、评分、导师材料 | `docs/plans/TASK1-PLAN.md` | 40/25/25/10 映射完整，用户选定创新、核心组件、AI 载体和删减线 |
| CODE | OpenCode | 已确认的 T1-PLAN | CODE handoff 与聚焦 commit | 实现未静默偏离计划；本地检查结果和未执行项完整 |
| TESTS | Codex | CODE handoff | T1 TESTS 报告及证据 | 自动测试、构建、交互、评分证据和平台边界全部裁决 |
| LEARNING | Codex | T1-TESTS VERIFIED | 简历与面试版复盘 | 用户能讲清项目、职责、亮点、难点、结果与真实性边界 |

OpenCode 是默认写入者；只有出现可复现阻塞且用户明确批准，Codex 才能作为 CODE fallback 接管。T1-LEARNING 未 `VERIFIED` 前不得启动 T2-PLAN。

## PLAN 强制约束

- 总计划必须逐项覆盖 Must、文件与模块、接口/状态/路由、依赖、测试、Android/H5 证据、风险、删减线和非目标。
- 必须按 40/25/25/10 写出“计划贡献、可见结果、实现位置、TESTS 证据和降级线”。
- 创新尚未决定时，Codex 只提交 2–4 个候选及用户价值、核心组件、AI 载体、评分收益、成本和风险；用户选择前状态为 `WAITING_USER`，不得 CODE。
- 最小趋势区域与 AI 标注可以作为高杠杆候选；通用图表、K 线和高级手势仍不是 Must。
- 计划变更若影响评分、范围、公开接口或验收，必须写回同一计划并重新获得用户确认。

## 题面能力合同

### 首页行情列表

- 展示股票名称、代码、最新价、涨跌额和涨跌幅，列表可滚动。
- 点击股票进入相同实体的详情页。

### 个股详情

- 展示名称、代码、最新价、涨跌幅、最高价、最低价和成交量。
- 路由参数显式校验；未知 code 进入可恢复状态。

### AI 分析

- 详情页至少提供一个用户可见的 AI 分析或解读区域。
- 具体主题和形态由用户在 PLAN 中选择，不预设为某个图表或卡片。
- 最终候选不应只有无状态静态文本；应具备至少一种展开、比较、信号定位、情景切换或详情联动。
- Mock 必须清楚显示数据/时效边界、风险或不确定性，并展示“仅作技术演示，不构成投资建议”。

## 工程与高分约束

- 默认使用仓库内确定性 fixture，不联网、不读取密钥。
- 行情规范化、字段格式化、页面状态、AI 内容与 UI 分离，并可独立测试。
- Android/H5 共享业务模型与状态；平台宿主只承担实际需要的生命周期和导航。
- 被称为通用组件的能力必须有聚焦接口、适用状态及至少两个真实 caller、场景或数据变体；拆文件不等于复用。
- 图表 DSL、K 线、成交量图、缩放、平移和高级手势只有被用户选为创新并写入总计划时才进入范围。

## TESTS 完成门

- Unit：正常/空数据、Provider 错误、未知 code、字段格式化、AI 内容确定性及计划中的核心组件。
- E2E：列表滚动、点击正确股票、详情字段、AI 载体、有意义交互和至少一个恢复状态。
- Build：执行 `scripts\doctor.ps1`、`scripts\verify.ps1`；H5 production bundle 与浏览器交互分别留证。
- Platform：Android APK 构建和设备运行分别记录；未运行真机/模拟器时不得写“Android 运行通过”。
- Score：40/25/25/10 每个申领项都有代码、测试、画面或文档的直接证据；Bonus 可以不申领。

## LEARNING 完成门

按 `docs/learning/_TEMPLATE.md` 输出通俗复盘：30 秒介绍、职责、用户路径、结构、三个难点、2–3 条简历表述和 8–12 个面试问答。无需学习具体 API 细节，但所有表述必须与 TESTS 一致。
